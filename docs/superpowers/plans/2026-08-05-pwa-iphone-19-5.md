# PWA 19.5:9 на iPhone — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Перевести игру «Азбука» на базовое разрешение 19.5:9 (1080×2340) с `stretch/aspect=keep`, залочить PWA в портретную ориентацию и задеплоить работающий билд на GitHub Pages, чтобы на iPhone 16/15/14 (19.5:9) игра занимала экран без полос и без «плывучести».

**Architecture:** Смена базового разрешения и режима растяжения в `project.godot`; перестройка вертикальных раскладок 9 сцен под высоту 2340; настройка PWA-манифеста (ориентация portrait); сборка Web-экспорта и деплой на `gh-pages`; визуальная верификация через Playwright (эмуляция iPhone) + ручная проверка на устройстве.

**Tech Stack:** Godot 4.6.3 (GDScript, .tscn), Web export (WASM + PWA), GitHub Pages, Playwright MCP (визуальная QA).

## Global Constraints

- Префикс git-команд обязателен: `GIT_MASTER=1 git ...`; push только через github-push skill (токен из `~/.config/github-tokens.json`, ключ `TestingInPractice/azbuka`)
- Валидация headless: автолоады работают только при запуске СЦЕНЫ (`godot --headless --path . <scene>.tscn`), не через `--script` с кастомным SceneTree
- После изменения сцен — `godot --headless --import --path .` для обновления кэша
- Целевое разрешение 19.5:9 = **1080×2340** (2340/1080 = 2.1667 = 19.5/9). Локальное окно: **540×1170**
- `DisplayServer.get_display_safe_area()` на web НЕ работает (только Android/iOS native) — safe area на iPhone решается через CSS/мета-тег
- Базовые UI-цвета сцен не менять; менять только вертикальное распределение
- Коммиты — только по явной команде пользователя (в прошлых задачах использовались `ui:`/`config:`/`test:`-стиль)

### Task 2: PWA-манифест — портретная ориентация

**Files:**
- Modify: `export_presets.cfg` (preset.0, секция options)
- Modify: `docs/` — нет (только конфиг)

**Interfaces:**
- Produces: в `index.manifest.json` при экспорте появится `"orientation":"portrait"` вместо `"any"`

- [ ] **Step 1: Сменить ориентацию PWA**

В `export_presets.cfg` заменить:

```ini
progressive_web_app/orientation=0
```

на:

```ini
progressive_web_app/orientation=2
```

(0 = any, 1 = landscape, 2 = portrait — enum "Any,Landscape,Portrait" по исходникам Godot 4.6; проверено после экспорта по содержимому `index.manifest.json` — `"orientation":"portrait"`.)

- [ ] **Step 2: (решение) meta viewport и safe area**

Текущий viewport meta (генерируется shell): `width=device-width, user-scalable=no, initial-scale=1.0` — **без** `viewport-fit=cover`. Это значит: в standalone-PWA на iPhone канвас ограничится безопасной зоной (не залезет под notch/статус-бар) — автоматически. Для MVP оставляем как есть (безопасный дефолт). Опциональный edge-to-edge (viewport-fit=cover + CSS `env(safe-area-inset-*)`) — вынести в отдельный спринт, НЕ в этот план.

- [ ] **Step 3: Commit**


**Interfaces:**

- Produces: все сцены корректно выглядят при 1080×2340; кнопки у нижнего края не «отклеиваются» от контента

**Подход:** при `aspect=keep` канвас всегда ровно 1080×2340 — сцены ДОЛЖНЫ быть свёрстаны под 2340. Элементы с `anchor_bottom = 1.0` останутся прижаты к низу, а расстояние между верхними и нижними элементами вырастет на 420 px. Правка: перераспределить вертикальные offset'ы так, чтобы группы элементов (заголовок/контент/кнопки) занимали новую высоту без больших пустот.

- [ ] **Step 1: Скриншоты-базлайн ДО правок (headless)**

Создать временный скрипт (не коммитить, удалить после):
`/tmp/azbuka_capture.gd`:

```gdscript
extends SceneTree

func _init() -> void:
	for path in [
		"res://ui/main_menu/main_menu.tscn",
		"res://ui/settings/settings.tscn",
		"res://ui/games/azbuka/azbuka.tscn",
	]:
		var scene: PackedScene = load(path)
		var inst: Node = scene.instantiate()
		root.add_child(inst)
		await process_frame
		await process_frame
		var img: Image = root.get_viewport().get_texture().get_image()
		var fname: String = path.get_file().get_basename()
		img.save_png("/tmp/azbuka_%s.png" % fname)
		inst.queue_free()
	quit()
```

⚠️ ВАЖНО: `--script` с кастомным SceneTree не регистрирует автолоады — для корректного рендера использовать `godot --headless --path . --script /tmp/azbuka_capture.gd` только если скрипты не требуют автолоадов; иначе прогнать через реальные сцены (см. Step 2). При необходимости — временно добавить сцену-раннер в `tests/`.

- [ ] **Step 2: Посмотреть каждую сцену, зафиксировать «разъезды»**

Run: `godot --headless --path . res://ui/main_menu/main_menu.tscn --quit-after 3` и то же для остальных 8 сцен.
Expected: все запускаются без ошибок. Визуальные пропорции — через экспорт и Playwright (Task 4) или редактор.

Правила правки (применять по ситуации в каждой сцене):
1. Если контейнер растянут на весь экран с `alignment=1` (центр) — он сам отцентрируется, правка не нужна (main_menu MainLayout — вероятно ок).
2. Если есть группа «кнопки внизу» с `anchor_bottom=1.0` и `offset_bottom=-40…-60` — НЕ менять привязку, а увеличить верхние/внутренние отступы контента так, чтобы пустота распределилась равномерно.
3. Если сцена имеет фиксированные offsets сверху (`offset_top=40`) и снизу (`offset_bottom=-40`) у одного и того же контейнера — оставить, контейнер растянется сам.
4. Игры с сетками (azbuka/letter_card) — проверить, что вертикальное выравнивание сетки не ломается при большей высоте; при необходимости сменить `size_flags_vertical` на `3` (expand+fill) у родителя.
