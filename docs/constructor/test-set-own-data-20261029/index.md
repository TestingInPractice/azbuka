# Собственный датасет тестового набора

Дата: 2026-10-29
Ветка: feat/test-set-own-data
База: azbuka-v2, 0fe1ee4

## Проблема

Инструмент `tools/fill_test_set` был жёстко привязан к `WORD_SET := 1` в
`tools/test_set_letter_writer.gd`. Он брал слово, картинку и звук из встроенного
набора 1, поэтому тестовый набор получался побайтово тем же содержимым, что и
встроенный. Родитель выбирал «Тестовый набор», открывал букву А и видел
«Авто́бус» с той же картинкой автобуса. Отличить свой набор от встроенного было
нельзя, и выглядело это так, будто выбор набора не применился.

Копировать любой из пяти встроенных наборов бессмысленно: это ровно та ошибка,
которую нужно убрать.

## Решение

Тестовый набор получил собственный датасет:

- 33 новых слова, которых нет ни в одном из пяти встроенных наборов;
- своя карточка на каждую букву: 1024x1024 RGBA, пастельный фон, крупная буква,
  слово без ударения, бейдж `ТЕСТ`;
- своя озвучка: `say -v Milena` и `ffmpeg` в 24000 Гц, моно, pcm_s16le, как у
  встроенных слов.

Инструмент больше не читает `AlphabetData` для слова, картинки и звука. Источник
медиа - `tools/test_set_data.gd` и каталог `tools/test_set_assets/`.

## Как перегенерировать ассеты

```sh
python3 tools/make_test_set_assets.py
python3 tools/make_test_set_assets.py --force
```

Без `--force` существующие PNG и WAV не перезаписываются, но проверяются
(размер, формат, длительность больше 0.2 с). С `--force` всё собирается заново.
Цвет карточки выводится из sha256 буквы, поэтому повторная сборка даёт тот же
результат. Скрипт печатает строку на каждую букву и возвращает 1, если хотя бы
одна буква не собралась.

После изменения ассетов нужно обновить импорт и закоммитить `.import`:

```sh
godot --headless --path . --import
```

## Повторное наполнение реального набора (2026-11-02)

Набор `c_51ba5d` («Тестовый набор») перезалит новыми словами. Команда та же,
что для любого набора; запуск из копии проекта под реальным `HOME`, чтобы
`user://` указывал на данные ребёнка:

```sh

HOME="$HOME" godot --headless --path /tmp/azbuka-refill2 \
  tools/fill_test_set.tscn -- --set-id=c_51ba5d --reset
```

### Найденный дефект инструмента и его исправление

Первый прогон со старой версией `--reset` удалил набор и создал новый id
(`c_c35395`): `delete_set()` не сохраняет id, а `progress.json` ссылался на
`c_51ba5d`. Набор был восстановлен из бэкапа, а инструмент исправлен:
`CustomSetsStore.clear_set_letters(set_id)` очищает буквы и файлы, сохраняя id
и имя. Валидатор `tests/validate_test_set_fill.gd` теперь проверяет и это:
id после `--reset` совпадает с прежним, имя сохранено, файлы старых букв
удалены.


## Остаточный риск

- Инструмент читает PNG и WAV из `res://` обычным `FileAccess`. В экспортированной
  PCK-сборке сырых файлов нет, поэтому инструмент остаётся dev-инструментом и в
  игру не входит.
- Перегенерация озвучки зависит от macOS-голоса Milena. Готовые WAV закоммичены,
  поэтому обычная работа и тесты от `say` не зависят.
- Карточка схематичная: буква, слово и бейдж. Она доказывает, что применился
  набор родителя, но не заменяет художественную иллюстрацию.
- Слова хранятся с комбинирующим ударением, как и встроенные. Если какой-то
  шрифт отрисует U+0301 сдвинутым, это поведение не изменилось этой работой.
- Валидатор сравнивает байты фикстуры с байтами встроенных PNG. Теоретически
  перекодированная копия той же картинки прошла бы проверку, но фикстуры
  генерируются детерминированно из буквы и не связаны со встроенными файлами.
