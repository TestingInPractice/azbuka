# Проверка работоспособности конструктора (2026-10-28)

Проверялось: работает ли конструктор пользовательских наборов после сведения веток на
`6a17457` — от открытия экрана «Мои наборы» до сохранения набора на диск.

Окружение: `godot 4.6.3.stable`, изолированная копия репозитория с переименованным проектом
(`config/name="Азбука-verify"`), то есть **отдельный `user://`** — данные ребёнка не
использовались и не менялись. Сценарии гонялись на настоящих сценах
(`set_list.tscn`, `set_editor.tscn`) и настоящем автолоаде `CustomSetsStore`, без моков.

## 1. Сценарная проба: полный путь родителя (21 проверка, все зелёные)

`journey.log`. Проба: два набора в хранилище (один с заполненной буквой «А» → «Арбуз»),
дальше — как руками.

| Шаг | Что проверено | Результат |
|---|---|---|
| 1 | Экран «Мои наборы» открылся сам, без внешнего `refresh()` | 2 строки, «Детский» и «Пустой», подпись «пока нет наборов» скрыта |
| 2 | Нажатие на строку открывает редактор | редактор виден, список скрыт, открыт именно нажатый набор |

| 8 | Удаление строки | список 3 → 2 |

## 2. Валидаторы проекта (12 сцен)

`suite/*.log`, сводка в `suite-summary.txt`.

Зелёные (11): `validate_custom_sets_store`, `validate_set_repository` (66),
`validate_custom_sets_integration` (130), `validate_constructor_ui` (335),
`validate_find_letter`, `validate_progress_set_id`, `validate_letter_translit`,
`validate_image_saver` (126), `validate_voice_record` (53), `validate_web_file_picker`,
`validate_ui_changes`.

Красный (1): `validate_word_sets`, 4 проверки. **К конструктору отношения не имеет и
существовал до наших коммитов:**

```
FAIL: get_word_data("А", 1)["word"] == "Автобус" (получено: Авто́бус)
FAIL: get_word_data("А", 2)["word"] == "Арбуз"   (получено: Арбу́з)
FAIL: набор 2 использует общий звук-заглушку (получено: res://assets/audio/арбуз_tts.wav)
FAIL: get_letter_data("А")["word"] == "Автобус"  (получено: Авто́бус)
```

Причина: в `content/alphabet_data.json` слова записаны с ударением (комбинирующий символ
U+0301), а тест ждёт слово без ударения. Файл последний раз менялся 2026-09-24 (`81b8b25`),
наши коммиты его не касались.

## 3. Визуальная проверка (окно, скриншоты + OCR)

Скриншоты сняты в окне 900×1600 (`screens/*.png`), текст распознан Vision OCR
(`screens/*.ocr.txt`).

Экран «Мои наборы» распознан целиком:

```
Создать набор
Алфавит
заполнено 2 из 33
Животные
заполнено 0 из 33
Удалить
Удалить
Назад
```

Редактор распознан: имя набора, «заполнено 0 из 33», строки букв с полями «Слово»,
кнопками «Картинка», «Записать», «Слушать», «Очистить», внизу «‹ Назад» и «Готово».
То есть вёрстка не разъехалась, текст не обрезан, пустых прямоугольников вместо строк нет.

## 4. Найденные несоответствия (не блокеры, отдельными задачами)

1. **Счётчик «заполнено N из 33» считает по-разному в двух местах.** В списке
   `SetListRow` берёт `CustomSetsStore.get_set_letter_count()` — буквы с любыми данными;
   в редакторе `_update_readiness()` считает только **полные** записи
   (`is_entry_complete()`: слово + картинка + звук). На скриншотах это видно буквально:
   список говорит «заполнено 2 из 33», редактор того же набора — «заполнено 0 из 33».
   Для родителя это выглядит как потеря работы.
2. **`validate_word_sets`**: расхождение данных и ожиданий теста по ударениям и
   звуку-заглушке (см. п. 2). Либо данные чистить от U+0301, либо тест сравнивать с
   нормализацией — решать отдельно.

## 5. Границы проверки

Проверено: логика экранов и хранилища, сохранение и перечитывание с диска, вёрстка
на 900×1600 без обрезки текста.

Не проверено: реальный тап и инерционный скролл на телефоне, доступ к микрофону и
системный выбор файла (в headless их нет), поведение на iOS Safari, звук в наушниках.
Это те же ограничения, что записаны в шапке `tests/validate_constructor_ui.gd`.

## 6. Команды воспроизведения

```bash

rsync -a --exclude '.git' <repo>/ /tmp/azbuka-verify/
sed -i '' 's/config\/name="Азбука"/config\/name="Азбука-verify"/' /tmp/azbuka-verify/project.godot
godot --headless --import --path /tmp/azbuka-verify

godot --headless --path /tmp/azbuka-verify res://tests/probe_constructor_journey.tscn
godot --path /tmp/azbuka-verify res://tests/probe_shots.tscn --resolution 900x1600
godot --headless --path /tmp/azbuka-verify res://tests/validate_constructor_ui.tscn
```

Сцены `probe_constructor_journey.tscn` и `probe_shots.tscn` — одноразовые, в репозиторий
не входят; их текст восстановим из логов и этой записи.
