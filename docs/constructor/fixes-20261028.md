# Исправление дефектов конструктора (2026-10-28)

Три дефекта, найденные при проверке работоспособности конструктора после сведения
веток (`verify-20261028.md`). Все три исправлены в `fix/constructor-mobile-recording`;
логи прогонов — в `fixes-20261028/`.

## 1. Предпросмотр не играл ogg и mp3

**Было.** `SetEditor._on_play_requested()` собирал `AudioStreamWAV` из сырых байтов
файла: `stream.data = FileAccess.get_file_as_bytes(path)`. Для wav это работало, для
ogg/mp3 контейнер получал чужие байты и играл тишину. m4a выдавался за рабочий звук.

**Стало.** Загрузка идёт общим загрузчиком игр: у `SetRepository` появился публичный
`load_audio_file(path)`, который делегирует `_load_audio()` — `res://` через `load()`,
`user://` по расширению (`wav`/`ogg`/`mp3`), неизвестный формат даёт `null` и запись в
лог. Редактор на `null` пишет `play_unsupported` и не трогает плеер.

**Почему так.** Загрузчиков звука было два, и они разошлись: игры поддерживали три
формата, редактор — только wav. Один вход (`load_audio_file`) закрывает расхождение
и не даёт ему появиться снова.

## 2. Счётчик «заполнено N из 33» считался по-разному

**Было.** Строка списка брала `get_set_letter_count()` — буквы с любыми данными.
Редактор считал только полные записи (`is_entry_complete()`: слово + картинка + звук).
Один набор выглядел как «заполнено 2 из 33» снаружи и «заполнено 0 из 33» внутри.

**Стало.** В хранилище появился `get_set_complete_count()` — единственный источник
числа для обеих подписей; им пользуются и `SetList.refresh()`, и
`SetEditor._update_readiness()`. `is_set_complete()` теперь тоже считается по полным
записям: «набор готов к играм» наступает, когда все 33 буквы заполнены полностью, а не
когда в них есть хоть что-то.

**Почему в эту сторону.** Контракт «полная запись» уже был закреплён валидатором
(`буква без звука не засчитана как заполненная`) и совпадает с тем, что буква без медиа
в играх не заиграет. Приводить к «любым данным» значило бы ослабить существующую
проверку, поэтому подтянут список, а не наоборот.

**Изменение поведения.** Набор, где у всех 33 букв есть только слово, больше не
показывает «набор готов к играм» — он честно показывает «заполнено 0 из 33». Игры при
этом не ломаются: незаполненная буква по-прежнему играет встроенными данными
(`SetRepository._custom_word_data` → `_builtin_word_data`).

## 3. `validate_word_sets` краснел на данных, а не на коде

**Было.** Тест сравнивал слово целиком, а в `content/alphabet_data.json` слова записаны
с комбинирующим знаком ударения (U+0301: «Авто́бус») — так их читает TTS. Плюс тест
требовал, чтобы набор 2 использовал звук-заглушку набора 1, хотя у набора 2 давно есть
свой файл (`арбуз_tts.wav`). Четыре проверки были красными не из-за конструктора.

**Стало.** Слово сравнивается без разметки ударения (`_plain()`), а озвучка набора 2
проверяется по смыслу: непустая и отличается от озвучки набора 1. Проверки не удалены и
не ослаблены до `contains`: сравнивается именно слово и именно отдельный файл.

## Границы

- Предпросмотр проверен по классу стрима, который получил общий плеер, а не на слух в
  браузере: headless-прогон звук не выводит.
- В репозитории нет mp3-файла, поэтому ветка mp3 в загрузчике проверена только на
  битом файле (не подменяется WAV). Настоящий mp3 стоит проверить руками на телефоне.
- m4a по-прежнему не читается загрузчиком: нужна конвертация при загрузке (отдельная
  задача), сейчас редактор честно пишет `play_unsupported` вместо тишины.
- Тап, инерционный скролл, микрофон и системный выбор файла headless не проверяются —
  те же ограничения, что записаны в шапке `tests/validate_constructor_ui.gd`.
